## Description

> …t-set flyer source
>
> - requirements.txt: re-exported with pillow. shared/flipp.py imports PIL at module level, so the Databricks App crashed on startup.
> - Proxy: check the lockout before the passcode. A locked-out guesser got 429 for wrong guesses but through on the right one, so guessing was unlimited and the status revealed the answer.
> - Forged visitor IPs: `make web` binds 127.0.0.1 by default (WEB_HOST=0.0.0.0 to opt out); the tunnel connects locally and a direct LAN client could set cf-connecting-ip. The lockout also has a global cap of 100 wrong guesses per 15 minutes that no IP header can dodge. Devices that already have the cookie keep working.
> - source="flyer" exempts an item from needing all four fields, and any client could set it. The API now keeps it only if the item really is a current listing (logic.is_listing, same comparison as matching), on POST /items and after edits; otherwise the item is saved as "manual".
>
> ## Summary by Sourcery
>
> Harden application startup, demo passcode protection, visitor identity handling, and flyer-source validation.
>
> Bug Fixes:
> - Prevent passcode lockout bypasses by checking per-IP and global failure limits before validating guesses, including guesses that forge visitor IP headers.
> - Ensure client-provided flyer sources are retained only for items matching a current flyer listing, reverting invalid or outdated claims to manual items.
> - Add Pillow as an explicit dependency to prevent application startup failures when image-processing modules are imported.
>
> Enhancements:
> - Bind the web development server to loopback by default while retaining an explicit option for trusted-device testing over a LAN.
> - Preserve access for devices with an existing unlock cookie during passcode guessing attacks.
>
> Build:
> - Add Pillow to the Python requirements.
>
> Tests:
> - Add API coverage for flyer-source validation, edits, unavailable flyer data, and passcode lockout behavior.
