## Description

> - A background poll (REMATCH_EVERY_SECONDS, default 300; off in mock mode) re-matches every user item in batches of 100 when any store's latest week_start changes, and once after each restart (covering in-memory retries lost on restart). Weeks are marked swept only if every batch succeeds.
> - Fix: a global max(week_start) treated every store whose flyer started earlier as stale, so one newer store emptied Deals. my_deals (views.sql), the LIKE fallback and the sweep now use each store's own latest week; the fallback keeps top-3 per store.
>
> ## Summary by Sourcery
>
> Implement reliable weekly re-matching and make flyer and deal selection current on a per-store basis.
>
> New Features:
> - Add an automatic background sweep that re-matches all user items when any store’s current flyer changes, including after restarts and for newly updated flyer contents.
> - Match each user item against the top three relevant items from every store’s own current flyer, using indexed search with targeted fallback coverage.
>
> Bug Fixes:
> - Use each store’s latest flyer week rather than a global latest week so deals remain available across stores with different flyer schedules.
> - Prevent failed or stale warehouse reads from being treated as successfully swept, and avoid duplicate match records during concurrent retries.
>
> Enhancements:
> - Track flyer signatures, batch re-matching work, and retry incomplete sweeps until all batches succeed.
> - Improve deal selection by applying deterministic score, price, and item ordering and calculating savings across one best match per store.
>
> Tests:
> - Add coverage for flyer-change detection, batched and retryable sweeps, per-store matching and fallback behavior, fresh warehouse reads, mock mode, and current-flyer deal selection.
