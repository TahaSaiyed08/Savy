## Description

> ## WS2 step 7: opt-in `DatabricksAIExtractor` (ai_query on the warehouse)
>
> Stacked on #15 (`ws2/backend`); review/merge #15 first. This PR only adds step 7.
>
> ### What
> `EXTRACTOR=databricks` runs every intake mode (receipt, product photo, manual, voice) through `ai_query` on the SQL warehouse, using the same prompts (`shared/prompts`) and the same `Extraction` JSON schema as Claude. **Claude stays the default**; nothing changes unless `EXTRACTOR=databricks` is set.
>
> - **Images:** uploaded to `/Volumes/realdeal/core/uploads/extract/<uuid>.<ext>`, read with `read_files(..., format => 'binaryFile')`, and always deleted afterwards, success or failure.
> - **Text (manual/voice):** `ai_query` on the text alone, no upload.
> - **Model:** `DATABRICKS_EXTRACT_MODEL` (default `databricks-llama-4-maverick`). The endpoint name can't be a SQL parameter, so it's checked against a strict pattern before being inlined.
> - **Slow statements:** new `databricks_sql.run_long()` polls up to 90 s, then cancels the statement. The 5 s budget for every other query is unchanged.
> - **Errors match Claude:** warehouse/model/upload failure → 502 (details logged, not returned); off-schema output → 422; HEIC → 415 before any upload; missing `DATABRICKS_HOST`/`DATABRICKS_WAREHOUSE_ID` → fails at startup.
>
> ### Live results (team workspace, demo inputs)
> | Input | Time | Result |
> |---|---|---|
> | Demo receipt | 23 s | All 10 lines, prices sum to $96.40, total $100.00 ✅. But `PCO FLD GRNS SLD` was read as "PC chicken breast" at 0.9 confidence ⚠️ |
> | Dairyland milk photo | 10 s | Dairyland 2% 1 L (0.95) + 2 alternates ✅ |
> | Voice clip | 4 s | milk, 2%, 4 l ✅ |
> | "the big Kirkland olive oil" | 3 s | Kirkland olive oil, nothing invented ✅ |
>
> Claude on the same receipt: ~12 s, all lines read correctly. That's why this is opt-in.
>
> ### Tests
> - 9 new tests: image path (upload → `read_files` → delete), text path (no upload), HEIC 415 before upload, 502/422 mapping (upload always cleaned up), settings checked at startup (including rejecting an unsafe model name), and `run_long` cancelling past its deadline.
> - `make lint` ✅ `make check-api` ✅ (no OpenAPI change). `make test`: 119 passed. The 2 failures are the existing WS1 Flipp tests that also fail on `main` (`test_flyer_items_table_row_adds_confidence_and_match_text`, `test_flipp_live_fallback_fires_when_search_and_like_both_miss`); unrelated to this PR.
>
> ### Docs
> README (overrides), `.env.example` (`DATABRICKS_EXTRACT_MODEL`), and `docs/plan.md` step 7 marked done.
>
> ### To try it
> Add `EXTRACTOR=databricks` to `.env`, restart the API, and check `/health` shows `"extractor": "DatabricksAIExtractor"`.
>
